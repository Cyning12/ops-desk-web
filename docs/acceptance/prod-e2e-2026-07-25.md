## 后端缺陷报告（移交后端 agent / 维护者，不在本仓修）

| # | 现象 | 证据 | 研判 |
|---|---|---|---|
| **F1** | 最新 graph 快照 `module_matrix` 为 null | `GET /api/ops/graph`：snapshot payload 完整但 `module_matrix: null` | `app/ops/graph.py` 直接透传 `OpsGraphSnapshot.module_matrix` 列——该列在最新快照未填充（导入未携带或生成器未写）。前端已防御性空态，非前端 bug |
| **F2** | chat `done` 事件 `model` 为空串 | done payload `{"latency_ms": 8010, "model": ""}`（本地 dev 同链路为 `deepseek-ai/DeepSeek-V4-Pro`） | 生产环境模型名未正确传入/配置缺失，建议查生产 `OPS_LLM_MODEL` 环境变量与 run 记录 |

## 观察项（不阻塞）

| # | 项 | 说明 |
|---|---|---|
| O1 | invite token 一次性 | 首个 token 未使用即 401——已被部署冒烟消耗（后端契约：`used_by_user_id` 条件）。建议部署流程与联调各发一枚 |
| O2 | 443 直连 TLS 重置 | 两次 401 后客户端 IP 被安全策略（疑似 fail2ban）RST TLS 握手；SSH 隧道绕行完成联调。建议核查 fail2ban 阈值，避免误伤正常运维 |
| O3 | `ci_status=success` 筛选结果 0 | prod PR 数据 ci_status 多为 null（导入源如此），非接口缺陷 |
| O4 | index.html 无 Cache-Control | 与 `docs/deployment/nginx-static-hosting.md` 建议的 `index.html no-cache` 不符，重部署后客户端可能读启发式缓存旧 index；建议 Nginx 补 `add_header Cache-Control "no-cache"` 于 `location /` |
| O5 | 无头环境局限 | 「console 报错/视觉渲染」类以资源可达性 + 产物完整性 + API 级证据佐证；建议维护者浏览器抽查一遍视觉层 |

## 总结论

**Web v1 生产联调验收通过**（13 pass / 1 partial-后端数据缺口）。前端在生产的全部功能路径（登录会话、四个数据页真实数据渲染、Chat SSE 全序列含 tool_result、SPA fallback、缓存策略）均有 HTTP 级证据支撑。后端 2 项缺陷（F1 module_matrix 空列、F2 done.model 空串）已具证移交，不影响前端 v1 验收结论。
